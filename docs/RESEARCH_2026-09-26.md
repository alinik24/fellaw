# Research refresh — 2026-09-26

## Findings that affect Fellaw

1. OpenClaw treats the workspace as private agent memory and keeps it separate from configuration, credentials, and sessions. Fellaw therefore keeps portable product instructions in Git while runtime/session state remains local.
2. Workspace bootstrap files include `AGENTS.md`, `SOUL.md`, `IDENTITY.md`, `USER.md`, and optionally `MEMORY.md`; only `AGENTS.md` is appropriate at the product repository root. Personal identity and user memory are intentionally not migrated.
3. OpenClaw supports per-agent workspaces and recommends verifying the resolved mapping with `openclaw agents list`. Recovery documentation uses this supported path rather than hidden Hermes state.
4. Long-term memory is Markdown-based, but raw daily notes and conversations can contain personal data. Fellaw does not copy the Fellow Traveler memory archive or Fellaw runtime sessions into product Git.

## What we borrow

- Workspace-as-code for portable instructions and skills.
- Explicit separation of workspace and runtime state.
- Doctor-driven validation and documented recovery.

## What we do not borrow

- Runtime credentials or session databases in Git.
- Raw personal memory as product fixtures.
- A second product-specific gateway or bot mutation path.
